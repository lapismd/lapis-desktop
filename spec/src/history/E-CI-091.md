## Decision and retained failure

The user directed that hosted Desktop tests run only on Linux and that macOS be
used only for builds. This follows repeated macOS runner acquisition failures
and the genuine native smoke failure retained in main CI run `43318741588` for
source `b28836dcaefd92e6e4755bad99edc2756c263189`. That attempt remains failed;
this change does not recast it as a pass.

The retained smoke diagnostic reported a complete document stuck at the
pre-bootstrap “Load the desktop shell” phase with an empty `#app`. Workspace and
services did not acquire runners. The policy change does not claim a repair for
that macOS startup mechanism and does not remove any quarantine.

## Contract and implementation review

- Quality, Unit, governance, catalog, audit, Validate and native Rust tests run
  on Ubuntu. Quality and Unit consume the Linux x64 private-package artifact.
- Hosted native preparation, smoke/workspace/services families, paired
  quarantine diagnostics, the Rust ARM64 diagnostic and the Native ARM64
  aggregate are removed. The separate native-quarantine workflow is removed.
- The macOS private-package producer and ordinary `ci:bundle` job remain as
  build/audit producers. No macOS job invokes a test task.
- Full exact-source qualification requires the complete Linux test inventory,
  the macOS ordinary bundle build/audit and both Linux target builds.
- Release preparation still requires all three archives. Install, reinstall,
  uninstall, data retention, visible-window and graceful-quit receipts are
  required only for Linux ARM64/x64. The macOS archive is explicitly build-only
  and unexpected macOS runtime receipts fail the candidate inventory.
- Explicit local macOS lanes, original assertions, deadlines, inventories and
  quarantine records remain intact. Linux/browser success does not qualify macOS
  WebView, window, focus, Keychain, lifecycle or backup behavior.

## Focused regression

After the implementation but before updating governed expectations, the exact
focused Node command covering CI planning/workflow, native-lane defaults,
release gates/publication and image consumers reported 67 tests: 39 passed and
28 failed. The failures were stale expectations for hosted macOS native jobs,
native-family planning and per-target runtime receipts; they were not hidden.

After updating the contracts and regressions, the same command reported 66
tests: 65 passed and one stale output assertion failed. That assertion still
expected `native_families=["smoke","workspace"]`; the planner correctly emitted
the governed empty hosted family inventory. The assertion was corrected without
changing implementation behavior.

## Acceptance boundary

This receipt can prove that workflow definitions and release candidate
validation enforce Linux-only test execution and macOS build-only status. It
cannot prove hosted success until the complete PR workflow passes. It cannot
qualify any macOS native behavior, resolve the retained startup failure, or
authorize publication by itself.
