Generated static catalog and browser artifacts are excluded from
repository-source traversal, formatting and commits.

## Requirements

Native AI admission and tools use exact named main-window grants. Tool frames
carry opaque identities and metadata, with no launch authority. The explicit
device-owned local-file profile admits Codex through a verified runtime under
`ai.md`; absence stays inert. No renderer executable selection is granted.
Actual mounted admission/recovery qualification retains the M10.2 gate; the
existing e2e transport fixture is independent. Notes owns the lazy native
factory and optional bundled registration. The main window's exact ACP-session
grant exposes only host-admitted operations; extra individual, default, wildcard
and remote plugin grants remain denied.

E-AI-042 follows the user's local-file priority. LD-GOV-001/002/004 retain
source ownership, evidence and original JJ milestone gates; file-backed AI does
not qualify deferred native-store capture or application-tool integration.

Checkout leases MUST remain held for created, running, paused or uncertain
workers; only a proven-absent recorded owner permits adoption. Release, cleanup
and adoption MUST require known completed owned runs and immutable container
identities; failed transport queries prove nothing. Workers MUST drop Linux
capabilities so permission checks cannot bypass DAC.

The user authorized verified local pnpm archives until the publication gate. The
ignored overlay verifies checksums/revisions, redirects matching ranges and
preserves tracked manifests/lockfiles. Fixes stay upstream; no source patches or
aliases. E-REPO-039–041 retain LD-GOV-004/005 for owned Settings/forge UI; exact
source revisions and Apache-2.0 / CC0-1.0 provenance remain local.

Counted lines exclude blank lines and comments. Inline tests count toward their
containing production file. Generated lockfiles, icons and build output are not
authored source. No initial file-size exceptions exist.

For the historical M4–M7 delivery session only, the user requested targeted
tests per slice and deferred full repository and consumer suites until M7
implementation is complete. Record deferred lanes and run them before aggregate
qualification. This does not change original milestone gates or the standing
test policy for later sessions.

The preferred source layouts are documented in `AGENTS.md` and `desktop.md`:
bootstrap at the source root, feature-grouped `components` and `lib`, and
application-wide `styles`. New code follows its owning responsibility. Moves
update live imports and acceptance entrypoints; historical evidence remains
immutable and resolves against its enclosing snapshot. Organization alone does
not authorize new functionality or resume a paused migration milestone. Native
service features, Tauri `host` adapters and debug-only `acceptance` modules have
separate owners. Only `main.rs` and `lib.rs` may live at the native source root;
the normal and canonical architecture audits reject other implementation files.
Moves update spec-first mappings and their regression cases without old-path
re-exports, path-routing attributes or weaker unsafe-code boundaries.

Evidence uses a JSON metadata block inside readable Markdown. Record independent
runs and all failed attempts. An appended record may resolve an older failure;
it cannot rewrite that result. Use `enclosing-change` for evidence in the change
being verified rather than inventing a future commit hash.

Evidence paths resolve against current files, actual base-revision deletions, or
the immutable record's enclosing snapshot and its deletion parents. Fresh
evidence cannot claim an unrelated historical path. Missing references still
fail closed; removing an obsolete component does not authorize rewriting its old
evidence.
