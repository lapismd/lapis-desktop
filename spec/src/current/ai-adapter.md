# Native adapter records and deferred capture

LD-AI-001/002 and LD-REPO-003 retain these original contracts. Active local ACP
setup is governed by [AI](ai.md) and [local setup](ai-setup.md); native-store
publication remains Deferred. This topic split changes no requirement or gate.

The native capture adapter maps the shared capture port to the runtime's
complete frame-batch callback. Native policy must inject admitted privacy, exact
scope and a durable receipt sink; the adapter selects no path, executable or
backend. The debug acceptance profile uses synthetic privacy and synced private
fixture records to exercise actual batch transport and withheld receipt
outcomes. It cannot enable ordinary Notes execution or qualify
AgentStore/ThreadStore, power-loss recovery or a production privacy policy.

Production ACP consumes each native event's complete before/main/after group
through the public client helper. Every frame in a multi-frame group retains its
native cursor and zero-based frameIndex in application provenance. Single frames
omit that field, preserving legacy record bytes and hashes. Both transcript
backends deduplicate by session, request, cursor and optional frame index; a
replay cannot discard a different frame from the same cursor. Present frame
indexes must be non-negative safe integers. Projection and offline reads retain
them without inventing provider sequences or native acknowledgements. The SDK
acknowledges only after the complete consumer callback returns; a coverage
failure remains unknown. This renderer prerequisite does not select production
native privacy, admit a target or enable JJ persistence. The
[local Codex profile](../../../docs/local-ai.md) uses vault-file transcripts and
the SDK's explicit unprocessed event profile, without a JJ capture writer. JJ
capture requires an explicit backend and rechecks current physical-vault/window
admission and exact generation; it never falls back. The adapter constructs
native privacy policy with an injected durable sink; it chooses no paths or
backend. A separate debug-only profile exercises real scanner/path/credential
handling through native transport with a private fixture sink and owned
temporary cache. That profile does not admit production targets or qualify JJ
publication. The native service journal implements the shared selected-store
capture port under an exclusive private profile lease. It retains only checked
sanitized candidate/preparation/confirmation DTOs, rechecks injected current
admission around bounded IO and atomically syncs each monotonic transition. No
detached write survives a dropped journal future. Private scope records retain
opaque capture context and a provider fingerprint; raw device paths and
credentials are excluded. Constructing the journal does not select a Notes
conversation backend, admit a target or replace the required native callback
drain.

Current JJ handles and private native IDs own preparation; the repository topic
governs its single ThreadStore publication/receipt recovery. Unknown outcomes
cannot enable execution. Cold API preparation/restart and managed chat/capture
retain separate gates; [tags and queues](ai-addressing.md) confer no authority.

## Shared Rust turn profile intake

resolution retains an immutable per-vault profile, target catalogue and sealed
environment before acceptance. Preparing another vault or refreshing settings
cannot replace that snapshot. Unknown scoped targets never fall back to another
vault's or the default provider. The native policy uses the admitted physical
scope and profile identity without acquiring the window's NativeHost mutex. This
preparation does not select the new chat owner; Tauri transport, retained Agent
screen adoption and real-provider/cold-application gates remain required.

Native target metadata declares the existing trusted runner's safe default mode
under Notes LN-CORE-009/010: Codex `read-only`, OpenCode `plan`, and `ask` for
other admitted runners. Resolve that runner through the immutable prepared
launch, never from renderer IDs or labels. This file-profile configuration has
no saved native mode override; explicit turn modes remain unchanged and still
pass native negotiation. Unavailable launch metadata must fail closed.

The staged `LAPIS_DESKTOP_AI_OWNER=core` startup profile selects the shared
native owner and reports that fixed selection to the shell. The renderer profile
remains the serving default until cutover; invalid selections fail startup. Core
selection denies legacy ACP execution. The same optional AI plugin ID therefore
cannot construct two transcript writers. The existing public Agent screen
observes native commands and portable files through the shared Notes
application-profile adapter.

Typed turn IPC checks the local main-window caller and exact current native AI
admission. Authorization and Core acceptance share the owned AI transition
guard; blocking IO and drain release NativeHost first. Losing a reply does not
abandon accepted work or cleanup. Reload suspends admission without stopping
native turns. Explicit disable/close drains before retiring AI/compute
authority.

Every turn frame carries its owning opaque vault-session token. Native admission
compares it to the current main-window lease while holding the AI transition
guard, before obtaining the Core client or accepting work. A callback retained
by an earlier vault cannot acquire the newer vault's authority after a switch.
The token cannot choose a root, executable or native generation.

The staged Core profile retains the shared public History screen in the right
sidebar by default. Selecting a conversation preserves History and opens or
reuses its exact main-area scope/conversation. New chat opens a local scoped
draft; restoring a view never dispatches a prompt. Qualification includes the
actual Tauri composer, portable files and cold restart with a protocol peer;
that fixture does not replace R2.3 actual-provider acceptance.
