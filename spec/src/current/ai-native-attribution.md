# Native agent attribution under implementation

E-AI-079 extends LD-AI-002/004 and LD-REPO-003 through the existing canonical
capture worker and retained reader. This is an unqualified draft while
verification is parked. Ordinary native composer/store adoption, complete
context/skills/memory and mounted restart retain M10.2/M13.3 gates.

## Presentation preferences and native authority

Canonical managed preparation may carry a bounded participant snapshot: saved
profile ID and label, preferred model and preferred effort. The fixed native
Codex selector still owns launch authority. Profile fields cannot choose an
actor, executable, root, environment, credential or provider. Repeating a
preparation cannot substitute its participant. Avatar data/URLs stay in the
owning profile, outside the native preparation and captured transcript.

Native validation retains a maximum 64 UTF-16-unit profile ID, eighty Unicode
label characters, 256 UTF-8 model bytes and the closed off/low/medium/high
effort set. Empty/control-bearing labels and unknown fields reject before
storing an idle plan. These are saved preferences, not observed runtime
configuration or evidence that a provider applied a setting.

## Committed host facts

New canonical capture uses the owned `notes-canonical-v2` scope and
`lapis-canonical-capture-scope-v2` identity domain. Native capture and private
message formats remain unchanged. Every incoming frame receives schema-one
Desktop facts containing native repository/thread/worker/request identity,
admitted client and optional participant/prepared-authorship relation.

The namespace is `lapisDesktop.host`. If the provider already used that key, its
exact value remains under `lapisDesktop.provider`, including an explicit null
value. Provider metadata cannot replace the host value. Both parts pass through
existing native sanitization and the same durable AgentStore receipt fence.
Source facts are structured captured evidence, not a renderer transcript blob,
extra conversation database or executable binding.

For nonempty human text, the worker first confirms the canonical message writer.
Its already-verified structured receipt supplies the human message, actor, exact
revision and original ThreadVersion. The worker retains at most 256 such request
associations. A repeated request must keep the same relation. Context, controls
and unknown/failed authorship do not acquire an invented human record. Separate
participants may reuse one stable human request with identical text; their
native workers/sessions remain distinct and recover the same authored revision
rather than publishing one human message per recipient.

The association is committed with each captured event that names that original
request. It records confirmed preparation, not successful provider delivery or
completion. A confirmed human message may remain without a captured reply; that
absence cannot be projected as a successful turn.

## Retained native projection

Canonical read pins retain their original companion graph beside the original
Agent snapshot. The existing eight-read limit, close fencing/drain and record
bounds remain. Source advancement and private creation/actor cache loss cannot
replace either snapshot. Retained-graph memory and large-history performance
still need qualification.

Only the known version-two Desktop native capture source, native-api/trusted
plugin provenance, exact privacy policy, source instance, worker, ordinal and
frame request may yield typed host facts. Repository/thread identity must match
the original canonical read. Original/legacy or unrelated producer fields stay
inert evidence. Unknown/malformed qualified host facts fail explicitly.

An authored relation must resolve in that original companion graph to the exact
human message, actor, thread, nonempty revision, original ThreadVersion and its
message-creation event. The request relation itself is native host provenance in
the captured fact; ThreadEvent has no request-ID field and its private ID
derivation is not reimplemented. No timestamp/text similarity can establish a
relation. The native read adds a typed optional Desktop projection while keeping
the exact sanitized observation payload and original page text.

## Embedded transcript presentation

The renderer validates the typed projection and canonical page origin. Native
profile labels survive later local renaming. Avatars resolve from the owning
saved profile by its ID, with the admitted client icon as fallback; metadata
never loads an avatar path or supplies a new profile authority.

The shared Transcript groups a captured turn with a human message only when the
current retained view includes that exact revision and actor. Edited revisions
and equal text cannot acquire the old association. Authored and captured event
identities remain distinct; legacy origins remain separate and historical
permissions stay inert. Preferred model/effort cannot be presented as observed
configuration. Document/Classic and the author presentation reuse the embedded
Design Core session shell.

Captured prompt text keeps its captured-source attribution even when associated
with an authored turn; that relation cannot assign injected text to the human.
Assistant presentation keeps the native session identity and uses the saved
profile identity only for presentation preference lookup.

The managed-agent catalog story uses a simulated native projection and local
profile avatar. It is a review fixture, not native receipt/graph or provider
qualification. Its native, decoder and presentation regression sources remain
unexecuted. Ordinary managed chat integration is the next implementation step.
