# Native application tools

[Local setup](ai-setup.md) extends stdio to admitted Lapis/OpenCode and adds a
private authenticated HTTP MCP adapter for Cursor. AppToolHost retains execution
and effect ownership.

M10.3 provider configuration is device-owned and exposed inside the existing AI
settings. Fixed provider metadata comes from the public native catalog; the
desktop excludes subscription OAuth. API keys are write-only inputs to native
Keychain custody, represented in persisted settings by opaque references.
Conditional settings saves retain an exact request identity and committed
receipt; uncertain saves retain their draft/request for observation or exact
retry. Provider changes apply to newly admitted workers and invalidate
discovery; running workers retain their captured configuration. No credential
enters a transcript, vault setting, browser storage, Debug output or diagnostic.

An AI panel accepts bridge events only for its own active or recorded agent
binding. An empty or unbound sibling view cannot display or persist another
conversation's tool captures, even when both share the application bridge.
Paired provider placeholders and application callbacks retain one original
namespaced display identity in either event order. A payload-free wrapper
completion cannot erase the captured application result. Native tool/request
identities and existing persisted records remain unchanged.

LD-AI-001/002/003/004 retain host-owned registry, vault scope, approvals and
local transcript files. TOOLS-01B/C connect that policy through the shared MCP
stdio engine. JJ persistence remains deferred. Source-only fixtures cannot
qualify the mounted Codex profile.

TOOLS-01B1 supplies authenticated transport and original-owner cleanup.
TOOLS-01B2 adds coordinator/approval wiring and scoped Codex launch admission.
Only a factory with its owned AppToolHost advertises MCP support. E-AI-047
qualifies installed Codex read, approved edit, pending-edit cancellation and
cold local History. Wider effect-fault qualification remains TOOLS-01C.

TOOLS-01B2 connects the existing coordinator and approval/event policy. Native
Codex tool targets are opaque aliases bound to one worker claim and the original
vault/window generation. Base Codex discovery stays tool-free. Raw MCP launch
declarations remain refused. The turn arms only after durable local intent and
context preparation, and terminal publication waits for tool callback and
transcript-event drain. Any unknown effect fences the session; no automatic
replay is offered. Exact reply acknowledgements may be reconciled without
executing a callback again.

The native main-window host registers an immutable bounded tool snapshot under
its current physical vault/window/admission generation and original application
binding. Only opaque bridge/invocation identities cross renderer IPC. Paths,
programs, private sockets, launch configuration and credentials remain native.
Unknown fields and stale or foreign bindings refuse before dispatch.

Each binding owns a fresh private temporary directory, Unix-domain socket and
memory-only random credential. Its trusted MCP launch file contains environment
references, never credential values. The bundled Notes executable's dedicated
stdio role runs before Tauri initialization and exposes no filesystem or process
API. Only the admitted native parent selects that role and its environment. No
credential appears in renderer data, transcript, Debug output or logs.

The helper authenticates before receiving its fixed tool list. Calls retain a
native opaque invocation identity distinct from provider/MCP numeric IDs. The
owning renderer invokes its existing AppToolHost, which revalidates
registration, conversation scope and required approval. The bridge does not
create a new tool implementation or infer permission from a tool name or
provider claim.

Policy is rechecked after approval/capture waits and before dispatch.
Cancellation releases the waiter but retains the execute promise for drain.
Errors after dispatch carry an unknown outcome; late unregister cannot turn them
into proven pre-dispatch refusal.

All IO, parsing and startup work runs on native workers; preparation and owned
calls report through the App status API. Frames, snapshots, active bindings,
connections and calls are bounded. No method accepts arbitrary native launches.
Cancellation is correlated and propagates to the original callback; an effect
that may have started remains unknown. No uncertain turn/tool is replayed.

Close/disable, root/generation changes, window destruction and exit fence new
calls before draining the original owned callbacks and native connection tasks.
Late results cannot publish into another binding. Failed drain remains visible
and retryable. Actual execution and provider lifetime are separate from the MCP
transport; engine closure alone is not a durable effect receipt.

Local Codex uses the existing advertised read-only provider mode. Application
writes still require AppToolHost approval under the selected host policy and
guarded native Vault API; read-only provider mode cannot bypass that policy.
File, comment and conversation context retain their exact existing persistence
rules.

Acceptance proceeds through native IPC/auth/expiry/cancellation fixtures,
ordinary controller/approval and schema tests, then real installed Codex read,
approved guarded edit, cancellation and cold cleanup in isolated vaults. Only
that mounted path enables the corresponding runtime capability. Broader
provider/platform/distribution and original packaged lapis-agent gates remain.
