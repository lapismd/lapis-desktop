# Shared-screen integration

Existing Desktop views mount complete public Agent and Repository screens.
Complete public screens own layout; the host owns runtime and authority. The
retired optional chat frame is removed rather than retaining an ignored parallel
layout.

## AI admission

Shared UI adoption uses complete public Agent screens. Desktop retains native
admission, exact requests, draft/storage ownership and controller disposal; UI
migration cannot enable deferred native conversation backends. The host's
existing Mira extension reaches the shared composer's public hook: Notes file
links, saved agent identities and profile details retain their exact syntax and
explicit App. Shared screen adoption cannot drop those decorations. The host
Markdown hook preserves leaf-node shape while decorating mentions so captured
handoff links remain renderable with prompt-context extensions.

A native first send can create its conversation before refusing execution. The
host adapter MUST correlate that captured error with the original attempt and
new conversation, suppressing only its duplicate host status while preserving
the exact retained draft; another conversation or a removed notice restores the
ordinary status. Both public composer status paths use that same host result.

## Desktop host

The isolated shared-screen migration preserves the existing Tauri window and
Notes AppShell. Shared screens occupy the existing view hosts; no new product
routes, installed profiles or native chrome are introduced. Disposal MUST finish
workspace projection and persistence while views remain mounted, then join
rendered shell cleanup before retiring plugin resources. This preserves exact
operation pins through cold restart and drains restored capture views on close.
Explorer's UI handles rejected late opens without changing programmatic failure
semantics.

## Source governance

Shared-screen adoption consumes public built package exports. After review, the
user-authorized migration is integrated into the default JJ workspaces and
temporary workspaces are retired; follow-up fixes use those defaults. Portable
dependency ranges remain tracked; temporary verified archive cohorts and
before/after catalogs retain source revisions and separate evidence.

## View registrations

retain matching IDs and use the same production integration after migration.

## Repository pins

History and Op Log mount the complete public Repository UI screens; portable
controllers retain admitted native readers and exact operation/revision pins.
Leaf File History uses its documented public RepositoryShell context because API
view mounts cannot inherit another component tree’s Svelte context. The history
leaf sets public AppShell inset, border, radius and 40px toolbar tokens for its
existing Notes sidebar, avoiding nested window chrome at that host boundary. Its
cards expose author details and an explicit View code action; commit subjects
are descriptive text. Op Log closes the containing diff column through its
shared header rather than through the operation metadata card. Blame's wrap
preference stays in the Desktop settings owner and enters the shared panel
through `wrap` and `onWrapChange`, retaining its existing key. Complete screens
retain the shared fixed horizontal canvas and compact composer geometry. Host
acceptance exercises those defaults and retained drafts rather than reinstating
the retired custom layout or three-line input override.
