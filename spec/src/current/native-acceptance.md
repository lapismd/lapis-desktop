# Native acceptance modes

Cold-process acceptance matches the complete Rust readiness output before
retaining a bounded tail. A listening driver socket alone cannot prove IPC
readiness; early evaluation can lose replies during navigation. Keep the bounded
startup deadline.

The explicit `test:desktop:api` lane uses a hidden native WebView for IPC-only
checks with macOS activation prohibited. It verifies native caller/frame policy,
vault lifetime and cold admission reset without visible UI or animation claims.
It never invokes foreground recovery, real pickers or popup proofs, refuses a
running acceptance application and checks its binary's background-mode marker
before launch. Background controls compile only in debug e2e artifacts. The
quiet default remains browser/catalog plus native services; the headed lane
retains the complete native UI/OS gate.

Native capture qualification keeps the shared runtime/host/client source, Notes
adapter and actual cold WebView evidence separate. The headed acceptance
inventory includes complete capture batches and withheld receipt outcomes. A
synthetic privacy policy and synced fixture candidate do not qualify production
redaction, JJ publication or unknown-write restart recovery. Ordinary execution
admission and original milestone completion gates remain unchanged.

[AI](ai.md) owns UI, JSONL and cleanup; [repository](repository.md) owns history
admission (E-REPO-006). Native scope gates retain execution authority.

The headed native acceptance inventory retains original ACP compatibility and
adds complete capture-group delivery with withheld-receipt/no-replay checks.
These cases use compiled synthetic providers and isolated profiles; they do not
enable ordinary execution or replace production privacy and JJ persistence
qualification. Foreground readiness remains mandatory.

Real privacy acceptance uses the existing native policy through the production
capture adapter. Its provider emits split workspace paths and exact credentials,
plus an unregistered detector fixture; all must be sanitized before candidate
storage and renderer delivery. The scanner cache is a native-owned disposable
temporary directory retained through processor closure. The synced candidate
sink remains synthetic and cannot qualify JJ durability or restart recovery.

The hidden native API lane separately qualifies ordinary conversation
preparation and exact receipt recovery across cold application restart,
preserving dirty notes and the JJ operation. It invokes the production command
and real Git ThreadStore without enabling an execution target. This prerequisite
cannot qualify a managed conversation, its capture processor or chat UI
recovery.

The quiet native API catalog retains History owner selection/status, paused and
cold cache rebuild, storage relocation, capture recovery and detached lifetime
regressions. These use hidden isolated WebViews; no foreground/window/OS or
provider acceptance is inferred.

Metadata adoption adds hidden typed-admission, renderer-default and foreign
caller denial, changed-root, closed-client, unsupported-contribution, detached
reconciliation and cold rebuild checks. The existing e2e-only hidden, unfocused
foreign-window fixture remains available in background mode; AI
enable/disable/revoke controls remain denied there. Actual Metadata/Search/Graph
view families also run with explicit native metadata selection; hidden reads
cannot replace their visible workspace gate. Native Search selection stays
unavailable in this metadata-only intake.

Native fixture tools MUST resolve from the selected runner installation before
hardening the application PATH. Repository fixtures retain that absolute JJ
identity instead of assuming Homebrew. The actual native process keeps only
`/usr/bin:/bin`; fixture tool discovery does not broaden application admission.
Shared native turn/queue peers MUST come from lapis-server at the same full Git
commit selected by the compiled app core, with an explicit hosted source
prerequisite. Retired Notes source paths do not supply those peers. E-CI-006
retains the original 97-pass/12-failure hosted result and separate repair proof.
