# Native acceptance modes

Cold-process acceptance matches the complete Rust readiness output before
retaining a bounded tail. A listening driver socket alone cannot prove IPC
readiness; early evaluation can lose replies during navigation. Keep the bounded
startup deadline.

The explicit `test:desktop:api` lane uses a hidden native WebView for IPC-only
checks with macOS activation prohibited. It verifies native caller/frame policy,
vault lifetime and cold admission reset without visible UI or animation claims.
It never invokes foreground recovery, real pickers or popup proofs, refuses a
running acceptance application and checks its binary's background-mode marker
before launch. Background controls compile only in debug e2e artifacts. The
quiet default remains browser/catalog plus native services; the headed lane
retains the complete native UI/OS gate.

Native capture qualification keeps the shared runtime/host/client source, Notes
adapter and actual cold WebView evidence separate. The headed acceptance
inventory includes complete capture batches and withheld receipt outcomes. A
synthetic privacy policy and synced fixture candidate do not qualify production
redaction, JJ publication or unknown-write restart recovery. Ordinary execution
admission and original milestone completion gates remain unchanged.

[AI](ai.md) owns UI, JSONL and cleanup; [repository](repository.md) owns history
admission (E-REPO-006). Native scope gates retain execution authority.

The headed native acceptance inventory retains original ACP compatibility and
adds complete capture-group delivery with withheld-receipt/no-replay checks.
These cases use compiled synthetic providers and isolated profiles; they do not
enable ordinary execution or replace production privacy and JJ persistence
qualification. Foreground readiness remains mandatory.
